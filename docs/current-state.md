## 2026-09-30 スマホで記録できない件・タスク整理・1か月目標の振り返り

- スマホで完了が押せない: 操作キーのログインは8時間（`Max-Age=28800`）で切れ、切れると記録ボタンが無効になり、ログインの入口はページ最下部だけだった。TODAY先頭・完了ボタン・振り返りカードに「接続して記録する」を表示。ログイン時間そのものは変更していない（延長は権限の判断が必要）。
- タスクの一括整理: 本人の依頼で、未完了タスクをまとめてアーカイブする `archiveOpenTasks` を追加（人間のログインのみ。外部AI・Workerは不可）。削除ではなく、履歴・完了記録・AI成果物は残り、状態を戻すと一覧へ戻る。画面で見た件数とサーバの件数が違えば止める。実行は本人がスマホの「やること」画面で行う（本番データへはこの作業環境から書き込まない）。
- 1か月目標（期限2026-10-01）の振り返り: 目標画面で達成基準を1行ずつ 達成/一部/未達 と事実・理由を記録し、分かったこと・次の1か月で変えることを保存（実績スナップショット `goalReviews`）。事実の無い「達成」は知らせ、状態の案は全基準の判定後だけ出す。目標を閉じる（未達成/達成/一時停止）のは本人の操作。TODAYに期限の2日前〜14日後の未振り返り目標を表示。
- 検証: ブラウザで、未ログイン表示→ログイン→表示解除、31件の一括アーカイブ（全45件は保持）、1か月目標の4基準の判定・保存（模擬中央保存 版2）→「未達成」として閉じる→TODAYの通知解除まで確認。本番の実データでの実行は未実施。

## 2026-09-30 カレンダーでPDCAを回す

- 従来の振り返りはアプリで「開始→完了」したTaskだけを集計していたが、計画はGoogle Calendarで立てておりTask操作はほぼ無いため、振り返りが空になりPDCAが回っていなかった。
- P=Calendarの予定、C=夜に○(できた)△(一部)×(できず)と理由を1つ、A=「明日ひとつ変えること」1行、に変更。アプリでTaskを作らなくても回る。
- 睡眠・休憩・予定なし・終日の予定は対象外。印を付けない予定は未記録で、できなかったとは数えない。△は半分で率を計算。記録時の予定名・時刻・色を写して残す（Calendarで後から消えても計画が分かる）。
- 記録は実績スナップショット `calendarReviews` として既存の版付き中央保存へ送る。サーバ側で日付キーと中身・結果・理由の形式を検証。
- TODAY: 昨日決めた改善を先頭に表示。18時以降は未記録の予定があれば「今日の予定を振り返る（3分）」を表示。振り返り画面の従来のTask実績は折りたたみへ移動。
- 検証: 実Google Calendar（9/29・9/30、15件）をブラウザに与え、9/29に○△×と理由・改善を記録→中央保存（模擬API、版2）→再読込で復元→TODAY先頭に表示→7日間集計まで確認。本番の実ログイン状態・実Redisでの読み戻しは未確認。

## 2026-09-30 カレンダー点検

- 9/16〜10/7の実Calendar（153件）を読み、管理しきれない原因を確認。OSとCalendarの差分は既存機能で見ていたが、Calendar自体の無理（同時刻の二重登録、時間の重なり、深夜作業→早朝予定で休息5〜6時間）は検査されていなかった。
- 実データで検出されたもの: 二重登録1件、部分的な重なり1件、休息6時間未満の夜2件、内側に入る枠2件（意図確認）。
- `【睡眠・回復】``【予定なし】`の枠は予定として数えない。内側に完全に収まる枠は意図的な場合があるため「確認」に分けた。
- Calendarへの書込は引き続き行わない。修正はGoogle Calendarで行い、「予定を再確認」で読み戻す。
- 未確認: 本番の実ログイン状態での表示。ローカルでは模擬データでモバイル幅の表示を確認した。
