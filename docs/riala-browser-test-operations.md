# RIALAブラウザ運営テスト

## 合意した方針 — 2026-09-17

- 定期チェックは **1日1回**。Codexのこのタスクにheartbeatを登録済み（ID: riala）。PC・Codex停止中の実行は保証しない。起動イベントそのものを検知する仕組みではない。
- 目的は顧客の定着、交流、コミュニティを好きになってもらうこと。公式KPIはない。AIは実行可能な改善案を提案するが、数値目標を公式目標として捏造しない。
- 情報源はログイン済みRIALAとRIALA Learning。公式APIはサーバー常時運用への選択肢であり、PC上のブラウザ運用の必須条件ではない。
- イベントは7日前・3日前の案内投稿を主とする。個別DMは週1回の関心に合う学習推薦を基本とし、イベント案内を機械的に追加して接触を増やさない。
- 新規会員Welcomeは名前だけ差し替える定型文を自動送信する方針をユーザーが承認。**現在はテスト期間なので送信しない**。対象と重複の検証後に実運用へ移行する。
- テスト中は送信、公開、予約送信の登録、会員情報の編集を行わない。

## 1回のチェック手順

1. ブラウザ状態を読み、正しいログイン先・運営アカウントを確認。ログイン切れでは止める。
2. `/posts` の運営アカウントの当日投稿と直近イベント告知を確認。投稿URL/画面上の投稿IDと日時を記録。システム告知や他の運営の同内容の告知も重複確認の対象にする。
3. `/events` で最新の開催日、本文、詳細リンクを確認。7日前・3日前をJST日付で判定。PC再開で遅れた場合、直近の有効な段階だけ候補にし、過去分をまとめない。既に近い内容の案内があれば自動の再告知候補から除外または確認に戻す。
4. `/members` と自己紹介から新規会員と明示的な関心を確認。名前だけで本人を同定しない。取得範囲・基準日・在籍・スタッフ区分が不明ならブロックとして記録。
5. DM画面でWelcomeと直近7日の推薦履歴を確認。閲覧できない履歴は未送信と断定しない。基準以前の既存会員に一斉Welcomeを作らない。
6. `https://riala-learning.vercel.app/` から実際の説明とリンクを確認し、関心に合う未推薦コンテンツを選ぶ。該当がなければ送らない。昨日紹介した内容を今日もう一度日次候補にしない。
7. `tmp/riala-test-runs/YYYY-MM-DD.md` に観測日時、確認範囲、候補、根拠、除外理由、未確認、次作業を保存。既存の日次記録へ追記し、確認済み履歴を消さない。会員情報は必要最小限にする。
8. 定着・交流に役立つ改善案をまとめる。例：最初に見るコンテンツの案内、投稿への質問、リクエスト募集、参加後のフォロー。本人が体験していないことを一人称で書かない。

## 合格前に確認すること

単体テストだけで実運用を合格にしない。会員の確認範囲・DM履歴の読み取り・実投稿履歴との重複照合・日次再実行・ログイン切れ・PC停止後の再開・イベント変更/中止・配信停止を、実画面で副作用なしに確認する。
実送信と公開後の読み戻しは未検証。テスト期間終了の判断後、許可された実対象への少数の実運用で確認する。テスト用の偽会員や公開テスト投稿を作らない。

## 実装の境界

`lib/riala-planner/recurring.ts` は7日前・3日前の投稿候補と定型Welcomeを扱う副作用のない処理。既存のGmail用Plannerとは別で、これを追加しただけでRIALAへ投稿・DM送信できるようにはならない。日次heartbeatはこの文書によるブラウザ照合を行う。
